# UI デザインルール

このアプリは音声入力を解析し、背景候補や前景素材を選んでプレビューし、STAGE へ出力する。画面は入力・解析・選択・出力の状態を混同させず、操作とその結果を近くに置く。

## 画面の役割

- 音声ソース、入力デバイス、開始・停止操作、入力状態を同じ領域にまとめる。現在どのソースから音を取り込み、入力中かどうかを常に読み取れるようにする。
- 入力レベル、BPM、解析状態は音声入力の近くに置き、それぞれ何を示すかラベルと単位で分かるようにする。実時間で値が変わっても、周囲の操作や状態表示を頻繁に移動させない。
- 背景候補として提案された素材と選択中の候補を区別する。前景素材も、選択して出力前に調整している状態と、STAGE に出力中の状態を区別する。
- 音声入力・解析の状態と、素材の選択・出力状態を一つの表示にまとめない。状態の説明は、それを引き起こす操作や対象の近くに置く。
- STAGE のプレビューウィンドウはメイン画面の操作領域と区別し、開閉状態をメイン画面から確認できるようにする。

## 共通の見た目

- 色、余白、角丸、文字サイズは `src/ui/theme.rs` の定義を基準にする。既存の `theme::panel`、`theme::caption`、`theme::badge` とテーマの色を再利用し、画面ごとに似た値を増やさない。
- `ACCENT`、`AMBER`、`RED`、`MUTED` はテーマでの意味を一貫させ、状態を示す場合は文言や形状も併用する。色の役割を画面ごとに変えない。
- 同じ見た目と操作を複数画面で使う場合は、現在の画面で使う共通部品としてテーマにまとめる。将来の用途だけを想定した部品は作らない。
- 主操作、通常操作、危険操作、選択中の表示を見た目とラベルで区別する。実際に選択・実行された状態だけを選択済みや完了として表示する。
- ボタンやタブのラベルは利用者が行う操作や開く内容を表す。内部名や曖昧な語だけで案内しない。

## 状態と通知

- 2状態（検出済み・未検出など）は対象ごとに一つの表示と状態名を使う。色は補助として使い、色だけで判別させない。
- 未設定・エラー・準備完了のような3状態は、3状態を区別できる表示を使う。アイコンや色を使う場合も、状態の文言を併記する。
- 音声入力の「準備完了・入力中・停止・デバイスなし・未対応・エラー」や、素材の「候補・選択中・ステージング・出力中」はそれぞれ実際の状態に対応させ、近い状態を同じ見た目にまとめない。
- 新しいエラーが起きたときは、該当する状態表示を一度だけ白から赤へ変化させ、短く揺らして注意を促す。画面がエラー状態にある間は揺らし続けない。同じ理由のエラーでも、利用者の再操作で再発した場合は新しい発生として一度だけ反応させてよい。
- 演出が終わった後もエラー状態、理由、利用者が次に取れる操作を読める形で残す。演出や色をエラー文の代わりにしない。
- エラーは問題が起きた操作や領域と結び付け、原因と次の操作を示す。同じエラー文を複数箇所に重ねて表示せず、一覧と詳細の両方が必要な場合は役割を分ける。
- 時間のかかる処理中は回転表示と処理中の文言を並べ、処理終了時に消す。成功・失敗後は結果や次の操作が分かる状態を表示する。

## 入力と操作

- 同じ目的の代替手段は同じ階層の選択肢として並べる。選んだ手段に必要な入力欄を対応付け、同時に使わない入力欄は隠すか無効にする。
- 入力欄には対応するラベルを付ける。縦に並ぶフォームでは、ラベル列と入力・選択欄の位置を揃え、どの値がどの項目に属するか明確にする。
- 縦に並ぶ同じ階層のボタンは幅と左右の端を揃える。ラベルが収まる幅を取り、ウィンドウが狭い場合も文字や操作欄を欠けさせない。
- egui 内に閉じられるパネルやダイアログを設ける場合は、右上に `×` を置き、ホバー時に「閉じる」と説明する。独立した STAGE プレビューウィンドウは、OS 標準のウィンドウ操作を使う。
- 選択状態は色だけに頼らず、ラベル、枠、アイコンなど既存のテーマに沿った手掛かりを併用する。
- 確認ダイアログは取り消しにくい操作に限り、対象と実行後の変化を説明する。実行とキャンセルの選択肢を明確に分ける。

## 目検

- UI変更のPRには、アプリの起動方法、必要な素材・設定、開始状態、画面上のラベル、入力値、操作順、結果が表示される場所と期待内容を含む手順を書く。
- 変更対象に関係する状態、入力経路、処理中・成功・失敗の表示を確認できる手順にする。ボタン幅やフォーム配置を変えた場合は、文字が収まることと狭いウィンドウで操作できることも確認する。
- 同じ前提・入力・処理の確認を重複させず、実行済みのチェック `[x]` はPR更新時も維持する。
